- Current review snapshot (2026-08-13): Prisma uses Better Auth models (`User`, `Account`, `Session`, `Verification`), but several routes/actions still reference removed legacy fields and models such as `clerkId`, `username`, `bio`, `passwordHash`, and `verificationToken`. Resolve the auth/data-model migration before feature work.
- Better Auth is the only user/auth management system. Clerk and Auth0 are not part of the target architecture. Legacy references should be removed as related code is migrated.
- Name ordinary Client and Server Components `name.client.tsx` and `name.server.tsx`. Next.js convention files such as `page.tsx` and `layout.tsx` keep their framework names.
- Keep components used by only one route in that route's `_components/` folder. Put genuinely reusable components in the root `components/` folder.
- Keep every `page.tsx` as a Server Component. Pages compose route-local `_components/` or reusable root `components/`; interactive behavior belongs below the page boundary.
- Put React-hook logic that works with business data into named custom hooks under the root `hooks/` folder. Keep small purely visual state local when extraction would add no domain value.
- Put reused CSS rules and reusable global style primitives in `app/globals.css`; keep one-off styling local with Tailwind utilities.
- Destructive auth/database migrations are acceptable while the database contains only disposable test data, but still state when a migration drops data.
- The planned MVP dashboard is the primary decision workspace: top navigation (`Dashboard`, `Explore`, and a disabled/coming-soon area), a `Welcome back, {userName}` greeting, a swipe deck, a Favorites preview that links to a dedicated page, a `Most likely` placeholder, and space for later metrics.
- AI-generated cards are transient until liked. A dismissed card is not stored in PostgreSQL; only a bounded in-memory undo history is kept. A liked card becomes persistent Favorites data and is deleted when the user removes it from Favorites.
- The active generated deck must survive a page reload but should remain browser-session scoped and be cleared when the relevant tab/browser session ends or the user signs out. Zustand with session-scoped persistence is being considered, but Zustand is not installed yet and the implementation is not finalized.
- The card-generation pipeline is still an explicit open design decision: generate a complete batch and make the user wait, or generate an initial batch and replenish it while the user swipes. Do not assume one approach until it is discussed and chosen.
- Generated images are optional for the MVP. First verify whether a suitable free image-generation provider exists for testing. If images are used, only images belonging to liked cards should be persisted in Vercel Blob; dismissed-card images must not become permanent orphaned blobs.
- `Most likely` is a future personalized recommendation generated by AI from at least 20 liked cards. It will eventually run through a free task scheduler at an undecided interval, but the MVP dashboard will contain only a placeholder.
- Persisted Prisma models, TypeScript types consumed by code, and runtime validation of AI responses are related but separate concerns. Avoid manually duplicating the same contract when a Prisma payload type or Zod schema can be the canonical source.
- The planned MVP dashboard metrics are: `Saved ideas` (total plus a recent-period delta), `Most likely progress` (`likedCount / 20`), and `Ideas explored` for the current browser session.
- Metric sources must remain explicit: Saved ideas and the Most likely threshold come from persistent Favorites data in PostgreSQL; Ideas explored is session-scoped state in Zustand/sessionStorage unless historical aggregate counters are deliberately added later.
- Future metric candidates are save rate, dominant interest categories, completed decisions per week, an activity streak, and average cards reviewed before a final decision. Prefer metrics that reflect delivered user value over decorative vanity statistics.
